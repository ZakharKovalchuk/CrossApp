# CrossApp

Наскрізний навчальний проєкт з дисципліни «Крос-платформне програмування».

## Предметна область: Бібліотека (Library Management)
- **Призначення**: Облік каталогів книг, фізичних примірників, читачів та операцій видачі/повернення.
- **Основні сутності**:
  - `Book` — каталог видань (назва, автор, ISBN, рік).
  - `BookCopy` — фізичний примірник книги з інвентарним номером.
  - `Reader` — читач бібліотеки (ПІБ, номер квитка, контакти).
  - `Loan` — запис видачі книги (примірник, читач, дата видачі, термін повернення).

## Архітектура та структура проєкту
- `src/Core` — бібліотека класів (Class Library). Містить незмінні моделі (`record EnvironmentReport`) та алгоритми збору системних параметрів (`EnvironmentInfo`). Не залежить від інтерфейсу виводу.
- `src/Cli` — консольний застосунок, який підключає Core через `ProjectReference` та відповідає виключно за форматування і вивід інформації.

### Планування каталогів Core на наступні етапи:
- `Core/Dto/` — record-типи формату передачі даних.
- `Core/Domain/` — сутності предметної області з інваріантами.
- `Core/Storage/` — абстракції та реалізації сховищ.

## Порівняння режимів публікації

| RID         | Режим               | Розмір  | Runtime потрібен? |
| `linux-x64` | self-contained      | ~77 МБ  | Ні                |
| `linux-x64` | framework-dependent | ~0.128 МБ | Так (.NET 9)      |

- **Self-contained** містить копію .NET Runtime у каталозі `publish`, тому працює на машинах без встановленого .NET, але займає значно більше місця.
- **Framework-dependent** містить тільки бінарний код проєкту, тому має мінімальний розмір, проте вимагає встановленого сумісного середовища виконання на цільовій машині.

## Лабораторна робота 4: Доменна модель та інваріанти

### Реалізовані інваріанти предметної області:
1. **Обов'язкові поля примірника**: `Id`, `Isbn` та `Title` не можуть бути порожніми або складатись лише з пробілів (`ArgumentException`).
2. **Межі року видання**: Рік видання повинен бути в діапазоні від 1450 до поточного року (`ArgumentOutOfRangeException`).
3. **Захист від повторної видачі**: Неможливо видати примірник, якщо він уже має стан `IsIssued == true` (`InvalidOperationException`).
4. **Захист від некоректного повернення**: Неможливо повернути примірник, який не був виданий (`InvalidOperationException`).
5. **Валідація дати повернення**: Дата повернення видачі не може передувати даті її відкриття (`ArgumentOutOfRangeException`).
6. **Захист від повторного закриття видачі**: Неможливо закрити видачу, яка вже має зафіксовану дату повернення (`InvalidOperationException`).

## Лабораторна робота 5: Сервісний шар та абстракція сховищ

* **Інтерфейс сховища:** `IBookStore` (`src/Core/Abstractions/IBookStore.cs`)
* **Реалізації сховища:** 
  * `InMemoryBookStore` — збереження стану в пам'яті за допомогою `Dictionary` (із демонстраційними `SampleData`).
  * `FileBookStore` — збереження стану у JSON-файлі (`data/catalog.json`) з кешуванням та збереженням змін на диск (`Flush`).
* **Сервісний шар:** `LendingService` (`src/Core/Services/LendingService.cs`) — бізнес-операції реєстрації, видачі та повернення книг без прив'язки до способу зберігання.
* **Composition Root:** `src/Cli/Program.cs` — точка конфігурації, де реалізація сховища обирається аргументом `--file`.
